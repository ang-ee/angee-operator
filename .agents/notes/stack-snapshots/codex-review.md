## Verdict

The service-owned save/restore contract and restic as the byte store are sound directions. The plan is not ready to implement as mergeable PRs. It overstates what the current hold lifecycle, `applyService`, `run_on`, and stream hashes guarantee. It also lacks a safe commit and recovery protocol for snapshot sets shared across stacks. The restore state machine needs to be specified before the runtime refactor.

## Findings

1. **Blocker — §14, phases 3–6.** **Evidence:** `manifest.go:749,1064`, `backups.go:231,267–273,893`, `platform.go:843`, `jobs.go:996`. **Problem:** Phase 3 removes `Capture` and `Backup` fields while the existing backup implementation still uses them, so that PR cannot build. Phase 4 removes the shipped backup path before phase 6 adds restore. **Fix:** retain the old internal fields until a cutover PR ships create and restore together; make every merge point buildable and recoverable.

2. **Blocker — §§8.8–8.10, Q8.** **Evidence:** The plan commits the manifest before optional verification; S10 shows changing a restic snapshot changes its ID; `backups.go:1011–1024` currently verifies before completing its receipt. **Problem:** A failed verify or receipt write leaves a visible manifest for a failed operation. The proposed `verified: false` cannot be written into that immutable manifest afterward. **Fix:** perform required verification before the manifest backup, commit last, and reconcile a committed manifest by `request_id` when receipt publication is interrupted.

3. **Blocker — §§8, 10.** **Evidence:** `platform.go:46,55,112–121` has a process-local lease; `backups.go:750–764` locks one root; S7 shows restic locks cover individual calls. **Problem:** Another root using the repository can forget an in-progress member or collect it as an orphan between calls. `--retry-lock` cannot protect the set. **Fix:** define a repository-scoped coordination protocol across CLI and operators, and collect only expired attempts proven inactive.

4. **Blocker — §9.2–§9.3, §16.** **Evidence:** `operator-backup-restore.md:100–110` forbids executing archive-provided commands; `platform.go:841–899` compiles commands from `angee.yaml`. **Problem:** Restic authenticates bytes, not the authority of a repository writer. A valid encrypted snapshot can carry malicious restore jobs; `--yes` bypasses the proposed review prompt. **Fix:** execute a separately trusted current or installed restore procedure after strict compatibility checks, or require explicit trust elevation for archived executable configuration. Validate every member ID, tag, path, image and command before altering the target.

5. **Blocker — §9.** **Evidence:** The plan downs and empties the stack before restoring files and secrets; D3–D4 demonstrate partial or empty state after restore failure. **Problem:** Missing members, unavailable images or sources, OpenBao failure, or incompatible jobs may surface after destruction. A safety snapshot might itself be partial. **Fix:** preflight the full replacement and a complete committed safety snapshot; stage to a sibling or private paths where possible; retain a durable rollback map and old state through successful apply.

6. **Blocker — §§8.6, 9.5.** **Evidence:** `backups.go:480–645,648–725` confines and separates source components; S11 shows restic’s stored paths depend on cwd and relative arguments. **Problem:** One `cmd.Dir=<root>` call cannot give external source components or answers above the root the proposed portable paths. A restic `--exclude` is not the current `os.Root` confinement. The restore command also leaves single-file target mapping undefined. **Fix:** specify a logical path map, use guarded staging or separate members for external components, inspect exact stored entries with `restic ls`, and restore through confined target operations.

7. **Blocker — §9.8–§9.12.** **Evidence:** `jobs.go:924–969`, `compose/backend.go:305–325`, `proccompose/backend.go:1208–1213`, `manifest.go:760,1068`. **Problem:** `applyService` suppresses dependencies, `waitServiceReady` polls every 250 ms contrary to the maintainer rule, and `run_on` is parsed but never executed. Normal apply therefore does not run the promised migrations. **Fix:** define a restore dependency graph and explicit post-restore jobs; use runtime-owned waits or pushed lifecycle events, with a process-compose spike for the needed behavior.

8. **Blocker — §§8.2, 8.10.** **Evidence:** `jobs.go:603–623,714–748`, `job_receipts.go:285–307`, `backups.go:836–1030`. **Problem:** Existing job holds stop services; a plain run intentionally leaves them stopped. `restoreJobHolds` stops failed recoveries. Backups currently use no holds, and no hook is told the outcome. **Fix:** design a snapshot-specific quiesce/release protocol that records prior service states, uses a fresh cleanup context, and reports or safely repairs interrupted release.

9. **Major — §8.4.** **Evidence:** S3 and D5. **Problem:** Count, SHA-256 and restic’s processed-byte count all describe the same received prefix. A producer that exits 0 after writing incomplete but nonempty data passes every proposed check. **Fix:** call these transport checks; require template-owned format verification or a scratch restore for recoverability, and collect both process exits and every pipe error.

10. **Major — §8.6, Q3.** **Evidence:** `backups.go:516–520,521–645,636–640`; S4. **Problem:** A second pre/post metadata walk misses same-metadata writes, cross-file inconsistency and swaps between Angee’s walk and restic’s open. Treating deletion as unchanged conflicts with today’s repository-tree rule. **Fix:** require holds, owner-created logical saves or filesystem snapshots for mutable files. Keep any metadata check advisory, not a consistency guarantee.

11. **Major — §§5, 8.1, 8.5.** **Evidence:** `backups.go:61–83,225–246`; S2. **Problem:** Owned paths are excluded even when their save is deselected, so a “complete” manifest can omit required state. Overlapping owners and extra staged files are unspecified; restic can record a FIFO without its content. **Fix:** define selection closure and partial-snapshot status; reject overlapping ownership and special or undeclared staged entries; compare `restic ls` against an exact expected file set.

12. **Major — §9.4, §9.13.** **Evidence:** `migrate_marker.go:17–61,75–113`. **Problem:** A phase-only restore marker cannot explain half-restored files, moved old paths, changed secrets and started services. A final receipt failure can leave a successful restore marked unfinished. **Fix:** record each irreversible step and its undo or forward action before executing it; define retry, reset and manual-recovery cases; reconcile receipt and marker after interruption.

13. **Major — §§9.5–9.8.** **Evidence:** `secrets/backend.go:17–31`, `platform.go:189–239,327–366`, `runtime.go:76–83`, `openbao.go:24–109`. **Problem:** “Secrets before render” is circular for a new OpenBao-backed root: backend configuration comes from restored `angee.yaml`, while OpenBao may need to start before secrets resolve. An archived backend path can also address the source stack’s namespace. **Fix:** require target backend configuration and credentials out of band, isolate the target namespace, bootstrap it before prepare, then write recovered secrets. The existing OpenBao health loop also conflicts with the no-polling rule.

14. **Major — §9 init, §8.6.** **Evidence:** `stack_update.go:323–328,552–589`, `stack.go:45–46,135–139`, `manifest.go:74,94–98`, `service_create.go:355–388`. **Problem:** Copier answers may live above `ANGEE_ROOT`; saved port leases are copied from the old host, while `StackPrepare` does not issue fresh leases. **Fix:** record the answers file’s render-target relationship and restore through Copier’s path rules. Remove or remap old leases and allocate replacements before first render; test a sibling restore with port conflicts.

15. **Major — §§3, 8.6–8.7, 9.7.** **Evidence:** `vcs/backup.go:44–67`, `gitdriver/backup.go:21–103`, `jjdriver/backup.go:84–146`. **Problem:** The VCS drivers expose backup plans, not an inverse. Git worktree metadata and jj’s `.jj/repo` and `store/git_target` pointers cannot simply be extracted at a new root. `fetch_published` also cannot recreate uncommitted files. **Fix:** specify and test driver-owned restore plans, pointer remapping and revision/operation verification before advertising VCS restore coverage.

16. **Major — §10 export.** **Evidence:** S9–S10; there is no `restic copy` spike in the evidence. **Problem:** The plan does not establish that destination snapshot IDs match the IDs embedded in `stack/snapshot.json`. A copied manifest can point at source-repository members. **Fix:** test copying into a newly keyed repository, map and verify destination IDs, then commit a rewritten destination manifest last and run an init round trip against it.

17. **Major — §§4, 10.** **Evidence:** S6–S7; `platform.go:730–735` uses the root rather than stack name for Docker identity because names are not unique. **Problem:** `snapshots.host` defaults to a nonunique display name; tagged manifests may be incomplete during concurrent forget, and `forget` can exit 0 for unknown IDs. **Fix:** use a stable unique repository namespace, full IDs and set-tag validation; report incomplete sets; de-commit before deleting members and verify absence afterward.

18. **Major — §§6–7.** **Evidence:** `compose/backend.go:32–60,201–237,483–495`, `compose/doc.go:12–27`; R3, R6–R7. **Problem:** Three `JobSpec` fields do not adapt the current `RunInput` seam, which consumes stdin for YAML and combines output. The Compose service model has no logging field. **Fix:** add a streaming runner with explicit stdin, stdout, stderr, inherited files and cleanup ownership; retain `RunInput` for existing paths. Test early producer/consumer failure and collect diagnostics before removal. R3 supports `-f /dev/fd/3` only with `--project-directory`.

19. **Major — §6 process-compose.** **Evidence:** R4 tests a job explicitly writing fd 3, not the proposed injected `exec 1>&3 3>&-` shim; `platform.go:1207–1225`, `proccompose/backend.go:1643–1679,1829–1884`; R6. **Problem:** The exact shell and Go `ExtraFiles` path remains unproven. `WaitDelay` currently sends no group kill, and killing the operator itself can still orphan a local job. Windows explicitly refuses transient local work (`foreground_windows.go:11–17`). **Fix:** spike the exact compiled shim with binary payloads and failures; signal and reap the owned process group on cancellation; state the SIGKILL-of-operator limit and keep Windows unsupported until it has a native lifecycle.

20. **Major — §§6–8, 11.** **Evidence:** `proccompose/backend.go:1841–1849` writes a 0600 config to OS temp; `platform.go:846–899` can resolve secrets into it; `platform.go:343–366` writes `run/secrets.env`; R7 shows Docker logs can copy dump stdout. **Problem:** “Never argv, env or disk” is too broad: repository URLs may contain credentials, backend credentials are in child env, files-mode staging is plaintext, and diagnostics can reach receipts. **Fix:** document each exposure, keep secret-derived URLs out of argv where possible, redact restic errors and URLs, separate artifact stdout completely, disable Docker logging for stream jobs, and test secret injection through every diagnostic path.

21. **Major — §11.** **Evidence:** `operator.go:199–205,735–747,1105–1124`; `operator-backup-restore.md:119–123`. **Problem:** Backup routes and receipts are admin guarded, but generic file and secret APIs still accept minted tokens with advisory scopes. New staging, exports and receipts must not become available through those surfaces. **Fix:** audit and exclude snapshot storage from generic file/log/GraphQL access; retain admin guards across every new route and receipt; coordinate scope enforcement where less-trusted actors can reach the operator.

22. **Minor — §7.** **Evidence:** S8; `jobs.go:470–492`. **Problem:** Mapping restic codes to replacement prose discards useful owner diagnostics. “Short” metadata deadlines are undefined, and `ANGEE_JOB_TIMEOUT=0` can leave data calls unbounded. **Fix:** preserve redacted restic error text with a stable Angee code and optional hint; specify finite deadlines per operation and accept non-JSON stderr lines.

23. **Minor — §§7–8.5.** **Evidence:** S11; `backups.go:860–864`. **Problem:** `--parent` must refer to the prior matching files member, not an unspecified “last manifest’s files member.” Reusing a stable staging path also lets crash leftovers be mistaken for new output. **Fix:** retain per-attempt staging, use exclusive output creation, and pass the explicit prior member ID or accept a re-read.

24. **Minor — §14 tests.** **Evidence:** R6, S3, S7, D3–D4, D7–D10, `job_receipts.go:85–129`. **Problem:** The tests emphasize success and fakes, while the dangerous transitions involve two runtimes, repository concurrency and process death. **Fix:** test interruption around every member, manifest, receipt, hold, marker, secret write and path move; include two roots, path attacks, OpenBao, answers above root, fresh ports, git/jj relocation, export round trips, partial selection and Windows refusal.

## Claims about current code verified as correct

- The roughly 1,300-line backup implementation stages under `state/backups/<id>`, creates a ZIP with entry hashes, verifies it, and publishes under `backups/archives/<id>.zip` (`backups.go:34–36,836–1030,1046–1226`). The proposal explicitly defers restore and retention (`operator-backup-restore.md:3–7,17–29`).
- The ZIP contains `recovery/angee.yaml` and plaintext `recovery/secrets.env`; secret values are absent from manifest JSON (`backups.go:936–959`). OpenBao’s captured env file is generated at `run/secrets.env` (`platform.go:343–366`).
- Capture jobs are declared on jobs, restricted to the two logical groups, excluded from normal compile, refused at manual entry points, and forbidden as dependencies or jobs with `holds`/`run_on` (`manifest.go:734–760,1043–1084,1119–1126`; `jobs.go:61–80`; `platform.go:708–722,841–845`).
- Discovery has the stated selection groups and global exclusions, reports named volumes as unsupported, separates workspace files from slots, and obtains source plans from VCS drivers (`backups.go:58–83,214–445,648–725`). Its service-state check examines declared mounts and persists; it does not discover every writable path (`backups.go:294–336`).
- The current walker uses `os.Root`, refuses repository metadata symlinks and special files, and fails when listed repository metadata disappears (`backups.go:480–645`). The ZIP writer compares size, identity and mtime for each file, not cross-file consistency or ctime (`backups.go:1061–1135`).
- `BackupStart` makes requests idempotent by `request_id` and selection digest, holds the mutation lease and root lock during the asynchronous run, and persists a pending receipt first (`backups.go:728–833`). Interrupted receipt recovery occurs on read and removes staging/archive (`job_receipts.go:62–133`). Backups do not become `LatestJobRun` (`jobs.go:209–221,1100–1105`).
- Compose transient jobs currently use `-f -`, combined output and cancellation-triggered removal; process-compose uses a 0600 temp YAML, combined output, unset stdin, SIGINT cancellation and a non-Windows process group (`compose/backend.go:55–60,189–237`; `proccompose/backend.go:1643–1679,1829–1884`; `foreground_unix.go:10–17`). R1–R7 support the plan’s runtime observations for the versions tested.
- `JobSpec` has no streams (`runtime/backend.go:158–164`); the VCS interfaces have no restore counterpart (`vcs/backup.go:44–67`); `secrets.Backend` has `Set` (`secrets/backend.go:10–35`). The backup REST routes are admin guarded and their receipts are hidden from non-admin callers (`operator.go:199–205,735–747`).
- D1–D10 support the PostgreSQL, SQLite and Redis claims. The exact template `pg_dump` command lives outside this Go checkout, so it was **not** independently verified against current Go code.

## Positions on Q1–Q8

- **Q1:** Agree with a clean release break, but keep old internals until create and restore ship together. Document migration of the parked Django branch and old archives.
- **Q2:** Do not enable local stream saves until the exact injected fd-3 shim and group cleanup pass an end-to-end spike. Seek the title fix from process-compose.
- **Q3:** Disagree with a default metadata consistency claim. Require holds, a logical save, or an owner-created filesystem snapshot for mutable state.
- **Q4:** Disagree with data-only as the default. Make it an explicit compatible partial restore; a full restore needs matching configuration and a trusted procedure.
- **Q5:** Agree that Django should derive its catalog from validated repository sets and receipts. Live views should use owner pushes.
- **Q6:** Agree with encrypted copy and explicit plaintext export, conditional on destination ID remapping and a restore round trip. Do not add another ZIP implementation.
- **Q7:** Agree with optional UI group labels; service identity and ownership must remain canonical, and `(group, name)` must be unique.
- **Q8:** Disagree with verification after commit. A declared create gate belongs before the manifest member; later drills and restic checks should have separate health evidence.
