**Verdict:** v2.1 is a stronger design, but it is not ready as a whole. It fixes the buildable cutover and gives create a verification gate. It still treats a root-local lock as proof about a shared repository, publishes success before quiesced services are released, and promises automatic restore recovery without defining how to resolve steps interrupted midway. The first review’s 24 findings are assessed below; “fixed” means the *plan* now specifies a credible resolution, not that code has been implemented.

### B. New findings

1. **Blocker — success precedes quiesce release.** **§8 steps 2, 10–12.** The manifest commits at step 10 and a succeeded receipt is written at step 11; only step 12 restarts previously running services. A release failure or crash therefore leaves a successful snapshot operation with writers stopped, while the committed manifest contains a quiesce record without its outcome. Evidence: [`stack-snapshots.md:415`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:415), [`stack-snapshots.md:474`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:474), [`stack-snapshots.md:486`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:486). **Fix:** release and record its outcome before committing the manifest; make receipt success the final durable operation result. If release fails, retain a failed receipt with a specific recovery action and leave members uncommitted.

2. **Blocker — the orphan rule cannot prove an attempt inactive.** **§10.** A different root with the same namespace has a different root lock and receipt directory; an absent receipt and age threshold do not prove its create has stopped. The 24-hour substitute when timeout is zero is particularly inconsistent with an unbounded job. S7 confirms restic’s locks are per invocation. Evidence: [`stack-snapshots.md:586`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:586), [`stack-snapshots.md:601`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:601), [`backups.go:750`](~/Work/angee-operator-stack-snapshots/internal/service/backups.go:750), S7. **Fix:** reject namespace reuse across live roots, including `--same-namespace` until replacement is established. Sweep only attempts whose failure is durably recorded by their owner; leave unknown attempts for an explicit, operator-reviewed forget.

3. **Blocker — tag-only reconciliation can certify the wrong request.** **§8 steps 0 and 11.** The preflight and recovery queries ask only whether a manifest has the namespace and `request_id` tags. They do not compare the stored selection digest, expected member set, or an existing failed receipt. Today’s `backupReceiptFor` explicitly conflicts on a changed digest. Evidence: [`stack-snapshots.md:393`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:393), [`stack-snapshots.md:408`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:408), [`stack-snapshots.md:484`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:484), [`backups.go:1267`](~/Work/angee-operator-stack-snapshots/internal/service/backups.go:1267). **Fix:** reconcile only one exact, validated manifest whose request digest and member identities match the pending receipt; conflicts must remain conflicts.

4. **Blocker — journal replay cannot distinguish “not run” from “ran, not marked done.”** **§9 Journal and step 12.** A crash after an aside rename, secret write, restore job, or migration but before the “done” write makes blind `--resume` repeat the operation and `--rollback` skip its undo. Step 12 then deletes aside paths before closing the journal and publishing the receipt. PostgreSQL’s restore into a nonempty database fails on repeat (D4). Evidence: [`stack-snapshots.md:524`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:524), [`stack-snapshots.md:574`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:574), [`stack-snapshots.md:577`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:577), D4. **Fix:** define per-step observable pre/postconditions and idempotent replay; stop for manual recovery when a job’s outcome cannot be proved. Commit restore success before optional aside cleanup, and keep undo material until that commit.

5. **Blocker — `--files-from-raw` loses the walker’s confinement.** **§8 step 6.** The current walker opens directory entries through pinned `os.Root` handles. The proposed handoff gives restic path strings to open later; a directory or link can change between the walk and restic’s read. The same gap applies to the claimed exact file set. S4 shows restic can accept changing files with exit 0. Evidence: [`stack-snapshots.md:453`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:453), [`backups.go:512`](~/Work/angee-operator-stack-snapshots/internal/service/backups.go:512), [`backups.go:603`](~/Work/angee-operator-stack-snapshots/internal/service/backups.go:603), S4. **Fix:** give restic a frozen, confined tree or an owner-created filesystem snapshot, then check its stored entries. A prior pathname walk alone must not be described as confinement of restic’s later read.

6. **Major — the compatibility fingerprint is too narrow.** **§9 Trust.** It hashes snapshot blocks and job declarations, while restore also depends on service runtime configuration, dependencies, persist targets, secret backend, and the image actually run. `applyService` uses the compiled service and suppresses its declared dependencies. A matching proposed fingerprint can therefore certify an incompatible “full” restore. Evidence: [`stack-snapshots.md:496`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:496), [`platform.go:750`](~/Work/angee-operator-stack-snapshots/internal/service/platform.go:750), [`platform.go:841`](~/Work/angee-operator-stack-snapshots/internal/service/platform.go:841), [`jobs.go:924`](~/Work/angee-operator-stack-snapshots/internal/service/jobs.go:924). **Fix:** version a canonical compatibility record covering the resolved execution specification, image digest, ownership and target path map, required secrets, and restore dependency graph. Specify per-member fingerprints for `--data-only`.

7. **Major — OpenBao bootstrap is undone by the archived config.** **§9 steps 4–5.** The plan takes target OpenBao settings out of band, then writes archived `angee.yaml`; normal secret resolution uses that manifest’s `secrets_backend` address, mount, path, and token. The destination may subsequently read or write the source path. The env-file path has the same relocation question, and `ReadDeclarations` captures declared secrets, whereas the existing env-file backend can hold additional values used by the runtime. Evidence: [`stack-snapshots.md:542`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:542), [`stack-snapshots.md:551`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:551), [`secrets/backend.go:17`](~/Work/angee-operator-stack-snapshots/internal/secrets/backend.go:17), [`platform.go:327`](~/Work/angee-operator-stack-snapshots/internal/service/platform.go:327), [`secrets/resolve.go:21`](~/Work/angee-operator-stack-snapshots/internal/secrets/resolve.go:21). **Fix:** define a target backend override that is written into the target manifest before any render, validate isolation, and state whether undeclared env-file entries are required recovery data.

8. **Major — clearing leases does not assign fresh ports, and answers may sit outside the journal root.** **§9 step 5.** Allocated ports are stored as `ports.*.value`; `port_leases` is a separate record. Allocation currently occurs in service/workspace creation, not `StackPrepare`. `locateStackAnswers` reads upward to the render target, possibly above the stack root, while the proposed journal and confined moves are rooted inside it. Evidence: [`stack-snapshots.md:551`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:551), [`manifest.go:173`](~/Work/angee-operator-stack-snapshots/internal/manifest/manifest.go:173), [`service_create.go:355`](~/Work/angee-operator-stack-snapshots/internal/service/service_create.go:355), [`stack_update.go:552`](~/Work/angee-operator-stack-snapshots/internal/service/stack_update.go:552). **Fix:** remap allocated port values and leases together before compilation; make the render target an explicit, guarded journal participant and preflight collisions with an existing answers file.

9. **Major — destination copy is not tied to the committed source set.** **§10 Backups.** Two tag-filtered `restic copy` calls can select every matching source member, including duplicates or members outside the committed manifest; checking only whether destination manifest tags exist makes a prior incomplete or conflicting copy a no-op. S12 proves one member-only copy and ID changes, not multi-member cardinality or interrupted-copy recovery. Evidence: [`stack-snapshots.md:614`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:614), [`stack-snapshots.md:626`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:626), [`s12_copy.md:5`](~/Work/angee-operator-stack-snapshots/.agents/notes/stack-snapshots/spikes/restic/s12_copy.md:5), S6. **Fix:** resolve and validate the source manifest’s exact full member IDs first, copy that set, verify one destination match per key and path, then copy the manifest. Make reruns validate an existing destination set.

10. **Major — “backup” does not yet imply off-host, and delivery puts destinations after cutover.** **§§4–5, 10, 14.** Schema validation requires only that destination and primary repository strings differ; two local paths qualify, despite the defined “off-host” meaning. P8 removes `/backups` and releases before P9 supplies destination copying, while P3 promises validation of every §5 rule. Evidence: [`stack-snapshots.md:185`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:185), [`stack-snapshots.md:266`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:266), [`stack-snapshots.md:752`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:752), [`stack-snapshots.md:774`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:774). **Fix:** either define destinations as named copies without claiming their physical location, or require an independently configured off-host destination. Move destination support before the cutover release, or explicitly scope that release to on-host snapshots and reject destination declarations until supported.

11. **Major — the no-polling rule is still violated by the proposed lifecycle.** **§6, §9 step 10, P1.** P1 says to fix today’s transient cleanup, whose implementation repeatedly calls `docker rm -f` on a ticker. Restore explicitly keeps `waitServiceReady`’s 250 ms status poll. Evidence: [`stack-snapshots.md:309`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:309), [`stack-snapshots.md:566`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:566), [`compose/backend.go:239`](~/Work/angee-operator-stack-snapshots/internal/runtime/compose/backend.go:239), [`jobs.go:936`](~/Work/angee-operator-stack-snapshots/internal/service/jobs.go:936). **Fix:** after the Compose client exits, make one bounded Docker cleanup call using a fresh context; use runtime-owned readiness completion or pushed events for restore, and let the owner’s timeout/error surface.

12. **Minor — P0’s rename inventory misplaces a symbol.** **§12, P0.** `BackupIdentity` lives in `internal/vcs/jjdriver/backup.go`, not `internal/git/backup.go` as the inventory states. Evidence: [`stack-snapshots.md:682`](~/Work/angee-operator-stack-snapshots/.agents/plans/stack-snapshots.md:682), [`jjdriver/backup.go:22`](~/Work/angee-operator-stack-snapshots/internal/vcs/jjdriver/backup.go:22), [`git/backup.go:52`](~/Work/angee-operator-stack-snapshots/internal/git/backup.go:52). **Fix:** correct the symbol inventory and rename all Go references in one P0 change; keep the `/backups` JSON tags unchanged as planned.
